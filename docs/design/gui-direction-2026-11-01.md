# GUI 视觉改进方向（2026-11-01）

本方案的材质、圆角、工具栏和首页模块布局已按后续指令实施；实际桌面/手机截图、修复记录及验证边界见 [GUI 实施验收](gui-implementation-2026-11-01/README.md)。下面保留原方案与前一步竖屏封面调整记录。

## 规范依据与已有基础

读取 [RC-UI-Style 最新 main 版](https://github.com/JDui/RC-UI-Style-Skill/blob/main/skills/rc-ui-style/SKILL.md)，以及其 [效果目录](https://github.com/JDui/RC-UI-Style-Skill/blob/main/skills/rc-ui-style/references/kiseki-effects.md)、[视觉系统](https://github.com/JDui/RC-UI-Style-Skill/blob/main/skills/rc-ui-style/references/visual-system.md)、[组件](https://github.com/JDui/RC-UI-Style-Skill/blob/main/skills/rc-ui-style/references/components.md)、[动效](https://github.com/JDui/RC-UI-Style-Skill/blob/main/skills/rc-ui-style/references/motion.md)和[接入配方](https://github.com/JDui/RC-UI-Style-Skill/blob/main/skills/rc-ui-style/references/effects-recipes.md)。本次读取日期为 2026-11-01。

新版增加了 Kiseki 参考模式、按用途选择表现强度、材质与主题分离、增强效果的生命周期与降级。下文是对 VRB 的适配建议，不代表这些效果已经在 VRB 实现，也不声称复刻了参考站。

当前项目已具备统一五项导航、滑动选中底板、浅色玻璃表面、分组首页、真实扫描反馈、媒体标签、响应式列表及减少动效路径。继续使用现有 Jinja 模板、CSS token 和脚本，不整包导入另一套 CSS/动画运行时。

样式顺序为基础 `styles.css` → 页面专用样式 → `liquid-glass.css` → `archive-ui.css` → `motion.css`。后续先整理已有 token 与最终覆盖值，再调整局部组件，避免继续叠加相互冲突的覆盖。

## 推荐方向：轻玻璃导航、稳定内容底、局部氛围

| 页面 | 表现强度 | 材质与布局 | 优先改进 |
| --- | --- | --- | --- |
| 首页 | `expressive`，仅局部增强 | 导航轻玻璃；视频封面保持原色；辅助模块用稳定浅底 | 将现有随机三段作为主模块；最近记录、收藏、那年今日形成有主次的 Bento，概览保持紧凑 |
| 时间线、文件夹、日历、收藏 | `restrained`，服务高频检索 | 内容区近实色；导航/筛选少量玻璃；沿用现有密度与容器自适应 | 统一工具栏高度、标签位置和信息显隐；保持封面完整及日期定位稳定 |
| 设置、维护 | `restrained` | 主表单 `solid`、嵌套区域 `flat`；保存栏保留薄玻璃 | 强化字段与分组层级、真实进行中/失败/部分完成状态，避免每个输入框独立模糊 |
| 播放器 | `restrained` | 原视频画面；稳定控制底板；小型菜单可轻玻璃 | 统一标题、元信息和动作间距；所有反馈来自实际播放/转码事件 |

主题沿用当前浅色与蓝色强调，不在本次方向中附带新增深色主题。材质变化不应改动选中状态、筛选、播放位置和输入值。

## 六项具体改进

1. **让首页分组更有主次。** 保留随机三段、最近、收藏、那年今日和概览的内容与入口，只调整分区跨度、对齐和背景层级。主模块更醒目，辅助模块更轻；不增加营销标题或大段空白。手机按现有任务顺序排列；按后续反馈，随机组三张在同一模块内纵向完整展开，保留「换一组」。
2. **收敛背景。** 当前两层 42/54 秒漂移色场改为按页面选择：首页可保留可关闭的轻氛围，视频库和设置建议默认静态。每屏一个主色场，颜色控制在导航、模块周边，不给视频或缩略图添加滤色与降亮度。
3. **分清控件、卡片、面板的圆角。** 普通按钮/输入建议 10–12px、卡片 14–16px、弹层 20–24px，保留 1px 边线和单层软阴影。已有五项导航的胶囊形态保留；筛选与状态可以继续使用胶囊，普通操作按钮逐步收敛到圆角矩形。
4. **统一工具栏与媒体信息。** 搜索、筛选、预览尺寸和扫描对齐；文件名、目录、时长和 HDR 标准保持各自信息层级。标签、收藏、菜单预留独立位置。延续“显示名称与目录”的用户选择，悬停与键盘聚焦行为一致；触摸端通过明确的详情入口读取完整信息。
5. **只增强发生变化的对象。** 复用现有滑动底板、菜单淡入和播放器分栏逻辑。按钮 120–180ms、选中 180–280ms、面板进入 220–320ms、退出 140–220ms 作为调优范围；不把整张媒体卡反复缩放。长列表追加、日期跳转和返回不重播首屏动画。
6. **给弱设备相同的信息与入口。** 减少动效时直接显示最终状态；不支持背景模糊或低性能路径使用有遮盖的实色面板。触控命中区至少 44px；200% 缩放时允许工具栏换行和面板滚动，不靠统一缩小字体解决溢出。

## 本轮已实施：准确比例的三列封面

| 视频显示比例 | 拼图 |
| --- | --- |
| 恰好 9:16、1:2 | 三帧横排，使用约 25%、50%、75% 时间点 |
| 其他 3:4 及更窄的竖屏，例如 2:3 | 继续四帧横排 |
| 接近方形的竖屏，例如 4:5 | 继续四宫格 |
| 横屏、全景 | 沿用既有生成方式 |

通过显示宽高的整数交叉相乘判断精确比例，沿用手机旋转与像素宽高比识别，不扩大到相近画幅。每帧保持完整画面，继续使用现有 WebP 参数。时间线的初始比例估算共用布局规则，图片加载后仍按真实尺寸排版。

新生成或重试的封面使用此规则。已有缓存可通过「设置 → 维护工具 → 重载竖屏缩略图」更新；本轮不自动扫描媒体或清空缓存。
